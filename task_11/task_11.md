Практическое задание 11
Условие
В рамках первого вебинара, посвященного объектно-ориентированному программированию, разбирались порождающие и структурные шаблоны ООП. Используя полученные знания, необходимо решить задачу добавления произвольной функциональности в уже существующий метод.

В оригинале задача сформулирована для решения на языке Java. Если вы используете другой язык, то метод test, приведённый в примере, нужно заменить на собственный код, а коллекцию List — на любое другое представление динамического списка объектов.

Задание
К заданию приложен файл task-9.0, внутри которого находится класс Magic со статическим методом test. Данный метод принимает объект типа List<Integer> и добавляет в этот список произвольное количество значений, после чего удаляет часть из добавленных. Необходимо вызывать метод test так, чтобы сразу после него можно было залогировать, сколько раз внутри метода test был вызван метод add у коллекции List.

Разберём задание на примере. Допустим, имеется следующий метод main:

public class Main {
    public static void main(String[] args) {
        List<Integer> lst = new ArrayList<>(List.of(3,4,5));
        Magic.test(lst);
        System.out.println("?????");
    }
}
В первой строке создан список из трёх чисел, во второй строке он передан в test. В третьей строке необходимо вывести на экран сколько раз вызывался метод add в test. Очевидно, что в данном решении:

невозможно вмешаться в работу test, т.к. это готовая библиотека;
невозможно вмешаться в работу ArrayList, т.к. это готовая библиотека;
невозможно сделать выводы по состоянию списка lst, т.к. буквально всё, что было добавлено, могло быть удалено.
Исходя из описанного, необходимо решить задачу, передав такую версию объекта, созданного в первой строке, которая позволит посчитать количество вызовов add. Обратите внимание, что поведение необходимо добавить именно ОБЪЕКТУ, созданному в первой строке.

ПО для выполнения задания и как развернуть окружение
Выполнять задание можно в любой IDE.

Формат результата
Решение должно быть представлено в форме исходного кода, включающего реализованный код и тесты демонстрации его работоспособности.

Код может быть прислан через платформу любым удобным способом:

ссылка на пул-реквест. В этом случае необходимо сделать репозиторий публичным или прислать инвайт на проверяющего;
файлы\архив с решением.
Критерии проверки
Решение оценивается по принципу «зачёт\незачёт».

Эталонное решение
К заданию приложен архив с JAR-файлом algos-11.0-sources.

В файле присутствует пример реализации всего необходимого кода, а также main метод, который при запуске показывает README с рекомендациями по реализации. При необходимости получить подсказки к решению сначала рекомендуется попробовать прочитать только README, и в случае, если он не поможет, — перейти к чтению готового решения.

JAR-файлы в общем смысле являются архивами, поэтому могут быть открыты любыми архиваторами.
