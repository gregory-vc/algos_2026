Практическое задание 14
Условие
В рамках вебинара были разобраны принципы построения чистого кода и подходов к построению процесса разработки ПО. Для практического закрепления результатов необходимо выполнить работу по рефакторингу готового решения с целью улучшения его качества.

Решение необходимо выполнить обязательно с применением систем версионирования (например, github), так как в рамках него требуется показать процесс применения подхода к разработке кода через TDD, что проверяется через историю коммитов.

В рамках работы также необходимо показать отдельными коммитами следующие шаги работы:

заливка начального решения;
написание тестов;
документирование;
рефакторинг;
написание тестов под новую функциональность;
заливка функциональности для «красного» теста;
заливка финального решения.
Финальное решение (после выполнения всех шагов) и история коммитов являются объектом проверки. Задание ориентированно на работу с Java-кодом.

При желании представить решение с использованием другого языка программирования необходимо перевести код стартового условия на желаемый синтаксис и применить профильные технологии выбранного языка для документирования и тестирования.

Задание
В рамках разработки интернет-магазина был реализован сервис обработки заказов, показанный ниже.

public class OrderService {
    public double calc(List<Item> items, String type) {
        double s = 0;
        for (Item i : items) {
            s += i.getPrice() * i.getQuantity();
        }

        if (type.equals("VIP")) {
            s = s * 0.9;
        }

        if (type.equals("NEW")) {
            s = s * 0.95;
        }

        if (s > 1000) {
            s = s - 50;
        }

        return s;
    }
}
А
также был разработан DTO для товаров.

public class Item {

    private String name;
    private double price;
    private int quantity;

    public Item(String name, double price, int quantity) {
        this.name = name;
        this.price = price;
        this.quantity = quantity;
    }

    public String getName() {
        return name;
    }

    public double getPrice() {
        return price;
    }

    public int getQuantity() {
        return quantity;
    }
}
Как можно увидеть из кода, сервис принимает список товаров и тип клиента и рассчитывает общую стоимость всех товаров в корзине с учётом скидки, в зависимости от типа клиента.

Используя данный код, выполните описанные ниже шаги.

Шаг 1

Создайте новый пустой репозиторий (либо отдельную ветку в существующем) и залейте туда код, описанный выше. Структура проекта задаётся самостоятельно, однако она должна соответствовать типовым требованиям (пакеты, разделение папок на тесты / основной код и т. д.).

Шаг 2

Напишите тесты на ранее залитый код, проверьте корректность прохождения всех тестов, а затем залейте их в репозиторий.

Шаг 3

Добавьте JavaDoc документацию на метод calc с описанием сути метода, принимаемых параметров и возвращаемого значения.

Шаг 4

Выполните рефакторинг решения так, чтобы оно начало соответствовать принципам чистого кода. После всех изменений прогоните тесты повторно и при успешном их прохождении залейте решение в репозиторий.

Шаг 5

К имеющемуся решению добавляется новое условие:

>>> если заказ содержит больше 10 товаров, применяется дополнительная скидка 1%.

Необходимо модифицировать код исходного решения так, чтобы он поддерживал это требование. При этом важно придерживаться принципов разработки через тестирование (TDD).

ПО для выполнения задания и как развернуть окружение
Выполнять задание можно в любой IDE. Также необходимо выбрать какой-либо публичный хостинг для публикации репозитория (например, github) и соответствующее ему ПО для заливки своего решения (включая встроенные в сервис или в IDE). Репозиторий может быть как публичным, так и частным (в этом случае необходимо делать инвайт на проверяющего)

Формат результата
Решение должно быть представлено в форме исходного кода и ссылки на репозиторий, в котором будут видны коммиты, описанные заданием. Ссылку на репозиторий необходимо прислать через платформу.

Критерии проверки
Решение оценивается по принципу «зачёт/незачёт». Для положительной оценки решение должно иметь:

корректно функционирующий код (с учётом как начальных функций, так и добавленного на последнем шаге требования);
перечень коммитов, описанных заданием;
тесты и документацию на код.
При этом код должен соответствовать концепциям чистого кода.
