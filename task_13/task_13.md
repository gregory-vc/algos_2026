Задание
Практическое задание 13
Условие
В рамках вебинара, посвященного разбору архитектурных паттернов, разбирались вопросы реализации MV* паттернов. Используя полученные знания, внедрите возможность применять MV* подход на компонентах, ранее не умевших этого.

В рамках примера таких компонентов предлагается обогащать функциональность калькулятора, показанного ранее в теме про объектно-ориентированное программирование. Однако можно реализовать и оторванное от этого решение, например, для стандартных SWING компонентов из состава JDK. Точно также можно брать другие языки и фреймворки до тех пор, пока для них валидно применение MV* концепций.

Задание
В результате ранее выполненного задания по разработке объектно-ориентированного калькулятора должен был получиться код, ориентировочно похожий на пример ниже:

class Calculator<T> {
    Reader<T> reader;
    Writer<T> writer;
    Map<String, Operation<T>> operationMap = new HashMap<>();
    public void perform() {
        Data<T> data = reader.read();
        data = operationMap.get(data.operation()).perform(data);
        writer.write(data);
    }
}
Данный код включает в себя разделение ответственности, однако не соответствует MV* шаблонам.

Необходимо преобразовать имеющееся решение к шаблону MVVM, для чего следует выделить компоненты:

модель;
представление;
представление Модели.
После выделения компонентов необходимо организовать между ними общение, не включающее прямые вызовы друг друга.

ПО для выполнения задания и как развернуть окружение
Выполнять задание можно в любой IDE.

Формат результата
Решение должно быть представлено в форме исходного кода, всего решения, а также тестов проверки работоспособности.

Код может быть прислан через платформу любым удобным способом:

ссылка на пул-реквест. В этом случае необходимо сделать репозиторий публичным или прислать инвайт на проверяющего;
файлы\архив с решением.
Критерии проверки
Решение оценивается по принципу «зачёт\незачёт» по факту наличия всех ключевых признаков MVVM в представленном решении.

Эталонное решение
К заданию приложен архив с JAR-файлом algos-3.0-sources.

В файле присутствует пример реализации всего необходимого кода, а также main метод, который при запуске показывает README с рекомендациями по реализации. При необходимости получить подсказки к решению сначала рекомендуется попробовать прочитать только README, и в случае, если он не поможет, — перейти к чтению готового решения.

JAR-файлы в общем смысле являются архивами, поэтому могут быть открыты любыми архиваторами.
