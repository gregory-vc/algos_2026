Практическое задание 12
Условие
В рамках второго вебинара, посвященного объектно-ориентированному программированию, разбирались поведенческие шаблоны ООП. Используя полученные знания, необходимо решить задачу, используя поведение как объект. Хотя примеры кода и эталонное решение написаны на Java, приём по превращению поведения в объект может быть найден и в других языках программирования.

К заданию приложен код базового решения на Java и описание к требованиям его изменения. В случае применения других языков программирования код необходимо будет адаптировать.

Задание
Допустим, имеется база данных, хранящая набор записей в виде строк. Необходимо инкапсулировать эти строки и предоставить возможность запрашивать их, с указанием индекса записи в базе и типа данных, объект которого необходимо получить в результате. На рисунке 7.8 можно увидеть пример использования такой базы данных.

Рисунок 7.8
Запрос нулевого элемента валиден как со строкой, так и с числом, так как фактически все объекты хранятся в виде строк. При этом такая строка на самом деле может быть и числом, которое конвертируется в него при вызове метода get. Запрос строки с индексом 1 возвращает объект типа Point, который конвертируется из хранящейся в первом индексе строки.

База данных должна поддерживать конвертирование строк в любой мыслимый объект.

ПО для выполнения задания и как развернуть окружение
Выполнять задание можно в любой IDE.

Формат результата
Решение должно быть представлено в форме исходного кода, включающего следующие элементы:

реализованный код для класса Db и всю его инфраструктуру;
тестовое окружение с примером реализации Db трёх любых типов;
тестовые методы, демонстрирующие работоспособность предложенного решения.
Код может быть прислан через платформу любым удобным способом:

ссылка на пул-реквест. В этом случае необходимо сделать репозиторий публичным или прислать инвайт на проверяющего;
файлы\архив с решением.
Критерии проверки
Решение оценивается по принципу «зачёт\незачёт» по факту наличия решения, удовлетворяющего требованиям гибкости добавления новой функциональности.

Эталонное решение
К заданию приложен архив с JAR-файлом algos-12.0-sources.

В файле присутствует пример реализации всего необходимого кода, а также main метод, который при запуске показывает README с рекомендациями по реализации. При необходимости получить подсказки к решению сначала рекомендуется попробовать прочитать только README, и в случае, если он не поможет, — перейти к чтению готового решения.

JAR-файлы в общем смысле являются архивами, поэтому могут быть открыты любыми архиваторами.
