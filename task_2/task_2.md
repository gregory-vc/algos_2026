Практическое задание 2
Определение сложности алгоритма
Условие

Используя информацию о способах оценки сложности алгоритмов и о построении
алгоритмов поиска значений в массивах, необходимо разработать алгоритм,
определяющий в массиве одновременно минимальное и максимальное значение.

Можно выбрать любой язык программирования, однако примеры задания написаны
на Java. При использовании других языков необходимо написать функциональный аналог приложенного кода.


Задание

Разберём код, приложенный к заданию.

public record Result(int min, int max){}

public class Solution {
    public static Result findMinMax(List<Integer> lst) {
        int min= lst.get(0);
        int max= lst.get(0);
        for (int i = 1; i < lst.size() ; i++) {
            if(min> lst.get(i)) min= lst.get(i);
            if(max< lst.get(i)) max= lst.get(i);
        }
        return new Result(min,max);
    }
}
Такой метод проходит по списку чисел за O(n) и находит минимальное и максимальное значение
списка, используя 2n сравнений (без учёта сравнений в for). Для проверки работоспособности можно использовать тест, приведённый ниже.

Необходимо таким образом изменить алгоритм, чтобы при сохранении асимптотики O(n) уменьшить число сравнений.

Подсказка: существует очень известный алгоритм поиска за 3(n/2) сравнений.

public class MinMaxTest {
    @Test
    public void mainTest() {
        List<Integer> lst= List.of(1,2,3,4,5);
        Result res=Solution.findMinMax(lst);
        Assertions.assertEquals(1,res.min());
        Assertions.assertEquals(5,res.max());
    }
}

Формат результата

Решение должно быть представлено в форме исходного кода, включающего метод findMinMaxCompact, и теста на проверку корректности разработанного метода (аналогично mainTest).


Код может быть прислан через платформу любым удобным способом:

· ссылка на пул-реквест. В этом случае необходимо или сделать репозиторий публичным, или
прислать инвайт на проверяющего;

· файлы/архив с решением.


Критерии проверки

Решение оценивается по принципу «зачёт/незачёт» в соответствии с наличием или отсутствием решения обеих частей задания.


Эталонное решение

К заданию приложено два JAR-файла:

1. В файле algos-2.0 собрано исполняемое консольное приложение, визуализирующее оба способа представления сети и оба метода, требуемые в задании.

2. В файле algos-2.0-sources собран исходный код предоставленного решения.

Файлы JAR в общем смысле являются архивами и поэтому могут быть открыты любыми архиваторами.
